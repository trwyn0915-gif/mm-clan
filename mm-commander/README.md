# MM Commander

نسخه اولیه ربات مدیریتی اتحادیه MM برای Rubika Bot API.

## امکانات نسخه اول
- پاسخ به /start و /help
- نمایش شناسه کاربری با /myid
- پنل ساده مدیر با /panel
- انتشار متن در همان گفتگو با /post
- اعلام مسابقه با /contest
- اعلام نتایج با /results
- پاسخ‌های راهنمای ساده درباره قوانین و پشتیبانی

این نسخه فعلاً متن‌محور است. ارسال عکس/ویدئو، مدیریت اعضا و ذخیره‌سازی مسابقات در نسخه‌های بعدی اضافه می‌شوند.

## راه‌اندازی امن
1. در BotFather توکن قبلی افشاشده را باطل و یک توکن تازه ایجاد کنید.
2. Python 3.10 یا جدیدتر نصب باشد.
3. متغیرهای محیطی را در محیط اجرای خصوصی تنظیم کنید:
   - `RUBIKA_BOT_TOKEN`: توکن تازه بات
   - `MM_OWNER_IDS`: شناسه کاربری مدیر(ها)، با کاما جداشده
4. برنامه را با `python bot.py` اجرا کنید.
5. در گفتگوی خصوصی بات دستور `/myid` را بفرستید. شناسه خودتان را در `MM_OWNER_IDS` تنظیم کنید و برنامه را دوباره اجرا کنید.
6. سپس /panel و فرمان‌های مدیریتی فعال می‌شوند.

## امنیت
- توکن واقعی را داخل GitHub، فایل عمومی، پیام یا اسکرین‌شات قرار ندهید.
- فقط شناسه مدیر مورداعتماد را در `MM_OWNER_IDS` ثبت کنید.
- فرمان‌های مدیریتی فقط برای شناسه‌های ثبت‌شده فعال هستند.
- برنامه باید روی یک دستگاه یا میزبان مورداعتماد و روشن اجرا بماند.
- برای تست اولیه از گروه آزمایشی استفاده کنید؛ قبل از ارسال اطلاعیه عمومی، متن را بررسی کنید.

## نکته درباره اجرا
این مخزن فقط کد را نگه می‌دارد و به‌تنهایی بات را ۲۴ساعته اجرا نمی‌کند. برای پاسخ‌گویی دائمی، برنامه باید روی یک میزبان همیشه‌روشن اجرا شود. فعلاً هیچ سرویس پولی یا خریدی تنظیم نشده است.

## مستندات
Rubika Bot API: https://rubika.ir/botapi


## پایه شخصیت و حافظه (مرحله آماده‌سازی)
- `personality.py`: شخصیت فارسی شفاف و شوخ + ساختار پیام‌های سازگار با اتصال مدل زبانی.
- `memory_store.py`: حافظه محلی SQLite برای تاریخچه گفتگو و یادداشت‌های اختیاری اعضا.
- `social_state.py`: نمونه پیام‌های برنامه روزانه مجازی؛ این ماژول به‌تنهایی پیام ارسال نمی‌کند.
- این اجزا هنوز به حلقه اصلی بات وصل نشده‌اند و تا زمان اتصال امن مدل زبانی، پاسخ هوشمند تولید نمی‌کنند.
- پیام‌های ذخیره‌شده محلی‌اند؛ مسیر پایگاه داده با `MM_MEMORY_DB` قابل تنظیم است.
- برای شروع در گپ، باید شناسه گپ مجاز و رضایت/اطلاع اعضا تنظیم شود. ارسال خودکار باید محدودیت تعداد و ساعت سکوت داشته باشد.
- برای اتصال مدل زبانی، کلید API باید فقط به‌صورت متغیر محیطی روی دستگاه اجرا تنظیم شود و هرگز در GitHub یا گفتگو قرار نگیرد.
## اتصال گفت‌وگوی هوشمند (مرحله اتصال آماده شده)
- حلقه اصلی bot.py اکنون ماژول شخصیت و حافظه را فراخوانی می‌کند و از API سازگار با OpenAI Chat Completions پشتیبانی می‌کند.
- برای فعال‌شدن پاسخ هوشمند، مدیر باید در محیط خصوصی اجرا این موارد را تنظیم کند: MM_AI_BASE_URL, MM_AI_MODEL, MM_AI_API_KEY.
- MM_AI_CHAT_IDS: شناسه گپ‌هایی که پاسخ هوشمند در آن‌ها مجاز است. بدون شناسه، ربات به پیام‌های عادی پاسخ هوشمند نمی‌دهد.
- MM_MEMORY_CHAT_IDS: فقط گپ‌هایی که اعضایشان از قبل درباره ذخیره محلی تاریخچه مطلع شده و با آن موافقت کرده‌اند. این فهرست جدا از فهرست فعال‌بودن AI است.
- مدیر می‌تواند با /forget حافظه ذخیره‌شده همان گپ را پاک کند.
- پاسخ هوشمند در هر گپ حداقل ۱۵ ثانیه فاصله دارد (قابل تنظیم با MM_AI_COOLDOWN_SECONDS).
- این نسخه هنوز پیام خودکار زمان‌بندی‌شده ارسال نمی‌کند. فعالیت مستقل باید بعداً با رضایت گپ، ساعات سکوت و سقف روزانه اضافه شود.
- فایل .env.example فقط نام تنظیمات را دارد؛ هیچ کلید واقعی را در GitHub قرار ندهید.
- قبل از فعال‌سازی، اعضای گپ را از پردازش پیام‌ها توسط سرویس AI و ذخیره تاریخچه (در صورت فعال‌بودن حافظه) مطلع کنید.
